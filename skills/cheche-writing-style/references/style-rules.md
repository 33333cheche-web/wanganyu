# 文风规则与句式改造

> **例证说明**：本文示例句取自样本项目《凯西经营大脑》方案。其中「沃橙」是**该项目**的我方主体名、「凯西」是客户名，换到别的项目时请替换为当前项目的实际名称（见 `SKILL.md` 的「项目变量」）。**规则本身与项目无关。**

## 一、这份文风到底要什么

用户的原始描述：

> "文风要像一个正规的方案……去的不伦不类，断句很不适合人类阅读。"
> "你把自己定义为一个方案专家，要写得精炼有力，让'人类'能看懂且潜移默化地带着方案的煽动力，但这点不用太刻意。"
> "我要的不是为了改而改，要贴切、精炼、有力。"

拆成四个可执行的要求：

1. **正规方案体**——书面语，不是聊天、不是推文、不是海报口号。
2. **人类读得断句**——一句话读完是一个完整判断，不是被句号切碎的词组。
3. **精炼有力**——删得掉的字都删掉，留下的是动词和数字。
4. **不刻意**——煽动力来自事实本身，不来自形容词、排比、感叹。

## 二、好句式的三个特征

**特征一：主语 + 动词 + 具体结果。**
> 沃橙驻场，与业务共同建立口径、规则与技能。
> 凯西团队自己改、自己加，沃橙按需支持。

主语是谁、做了什么、产出什么，一读就明白。

**特征二：一句只装一个判断。**
不要在一句话里塞两个转折和一个补充说明。转折多了就拆成两句，或直接用分号并列。

**特征三：数字落地。**
> 12 月底管理层与大区经理先试用，问数准确率目标 85%；2 月底验收 95%。

一个"大概""较快""大幅提升"都不要，全部换成可核对的值。

**特征四：抽象必须落到看得见的东西。**（2026-10-14 新增）

一个词，如果听的人看不到实物，就换掉。这是最像 AI、也最伤人的一种写法 —— 不是句子不通，是**通篇没有一个能想象出来的画面**。

> ✗ 洗到「够用」就停 → 什么叫够用？
> ✓ 洗到**数算得出来**就停
>
> ✗ 干净 **≠** 把空格填满 → 符号只写给眼睛看，念不出来
> ✓ **有的格子空着是对的。箱子还没还回来，归还日期那格就该空着。**
>
> ✗ 由人说了算 / 由 X 承担 → 公文壳，读者要拆两层
> ✓ **碰上拿不准的，问人。**
>
> ✗ 空着不等于错 → 得先懂"错"是什么，才知道这话在说什么
> ✓ **有的格子空着是对的，别填。**

⛔ **为某一次教学 / 汇报临时造的词，一律换成大白话**：止损、界线、判据、够用、三要素……
✅ **行业本来就有的术语照旧保留**：口径、卡点、打通、留痕（这些读者在业务里天天见，不是自造）。

**判断方法：这句话对着人说一遍，他脑子里有没有画面？没有，就重写。**

## 三、句式改造对照

| 病征 | 反例 | 改法 |
|---|---|---|
| 碎片断句 | 数据分散。响应慢。洞察浅。 | 数据分散在多个系统，临时分析需要等待。 |
| 主语缺失 | 需要先把数据理清楚 | 沃橙先把数据整理成 Agent 易读、易算、易追溯的形态 |
| 口号化 | 既要快，又要准！ | 速度与准确率同时达标 |
| 第二人称 | 帮你把月报做出来 | CE 直接获得生成好的月报 |
| 反问堆叠 | 谁来改？怎么改？ | 更换供应商后，凯西侧无人可改 |
| 对立式修辞 | 不是把数据搬过来，而是整理成…… | 我方建设的价值：把数据整理成 Agent 易读、易算、易追溯的形态（**直接给判断**）。**非必要不用**：确有必要时全篇只留 1 处；不要换成"不只是……更要……"，那是同一动作换皮。见 `banned-words.md` 用量条款 |
| 权力归属口语 | 这个归我们管 / 归凯西所有 | 由沃橙负责 / 为凯西所有 |
| 程度空转 | 其实非常关键 | 关键 / 决定上线与否 |
| 黑话 | 拉通、抓手、赋能、闭环 | 打通、方法、覆盖、全流程；或写具体动作 |
| 抽象自造词 / 符号 | 洗到「够用」就停 / 干净 ≠ 填满 / 空着不等于错 | 换成看得见的东西：洗到**数算得出**就停 / 有的格子空着是对的 / 拿不准的**问人** |
| 标题与正文重复 | 标题"取数提速"；正文"取数更快了" | 标题给结论，正文给依据与数字 |

## 四、"不要为了改而改"——反面清单

这几类是改稿中最容易犯的错，都是实际发生过的：

1. **同义替换**。把原文里有力度、有画面感的词换成平庸的书面词。原文如果已经贴切，不动。
2. **动钦定术语**。用户点名保留的说法（"卡点""打通""召唤"）不要"顺手优化"。
3. **制造重复**。把标题的措辞抄进正文说明，改完标题和正文说了同一句话。
4. **只改不判断**。机械替换跑完就交，没有一页一页读上下文，导致改后语义偏移。
5. **改结构**。动了标题、页序、页码、交叉引用——这些属于结构层，不动。
6. **改掉功能**（最隐蔽的一种）。形态没变，但职能变了：标题被改成解释句、被加上"现状：""小结："这类归纳标签；图注被写进结论；承诺里的限定词被拿掉。
   判别方法只有一个：**改完以后，这个位置还干不干它原来的活？** 见 `edit-discipline.md` 第一节。

## 五、动手前的自检

每改一条，先答这几问：

0. **这个元素在页面里干什么？**（标题 / 副题 / 图注 / 承诺……）改完还干不干这个活？
1. 这句原本想说什么？
2. 我的新表述是更贴切，还是只是换了个说法？
3. **这条改动对应哪一条规则？** 指不出来就不要改。
4. 主语有没有省掉？
5. 是不是和标题 / 相邻元素重复了？
6. 有没有把有力度原词换成平庸词？
7. 加长后会不会撑破版式（见 `cheche-html-deck-edit` 的版式红线）？

**第 0、1、3 问答不上来，就别改。**

改完全稿再过一遍 `edit-discipline.md` 第九节的验收清单。

## 六、交付时怎么解释改动

说明列写"为什么改"，不要写"改得更好了"。用这三类措辞：

- **统一自称**：全文以项目主体名指本方（样本项目为「沃橙」），不再使用指代不清的「我们」。
- **用词书面化**：去掉口语化、口号化表达，改用方案书面用语。
- **句式规范化**：拆掉「不是……而是……」句式（确有必要时可保留 1 处，见 `banned-words.md` 用量条款） / 数字与单位写法统一。

需要点明原意时补一句：
> 「接着用」偏口语，改为「继续沿用」——语义不变，语气更书面。
