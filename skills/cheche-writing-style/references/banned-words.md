# 禁用词 · 慎用词 · 保留术语

三级清单。**A 级出现即改；B 级看语境，改前必须读上下文；C 级是钦定术语，改了是减分。**
（唯一例外是 A 级里的"不是……而是……"——它不是禁用而是限量，见下方**用量条款**。）

## A 级 · 硬禁用（其中「不是……而是……」一项按用量条款处理：限量，非禁用）

用户明确点名或反复纠正过的。

| 词 / 句式 | 为什么禁 | 改法 |
|---|---|---|
| 兜底 | 工程口语，方案里显轻率 | 保底 / 由 X 承担 / 作为最后一道保障 |
| 接得住 | 口语，且暗示被动态 | 承接 / 接管 / 覆盖（按语义选） |
| 坑 | 口语 | 风险 / 问题 / 隐患 |
| 「这个归 XXX」 | 口语化归属句式 | 「由 XXX 负责」「归属 XXX」 |
| 「不是……而是……」 | 对立式修辞：先立一个读者并没有的误解，再把它推翻。方案里显得在辩解 | **默认直接陈述后半句**（首选）。**不是绝对禁**——确有必要时全篇只准留 1 处，见下方「用量条款」。「不只是……更要……」「不仅……更……」是同一动作的换皮，不算"必要" |
| 「爬」（如"从哪一级开始爬"） | 暗示低姿态、吃力感 | 「从哪一步做起」「从哪里起步」 |
| 咱 / 搞定 / 玩意儿 / 一把梭 / 完事了 | 口语碎片 | 书面动词 |
| 第二人称煽动（"让你""帮你"） | 方案是陈述，不是说客 | 改为角色主语 + 动作 |
| **自造的抽象词**（止损 / 界线 / 判据 / 够用 / 三要素…） | 为某次教学或汇报临时造的词。读者看不到实物，只能猜 | 换成具体动作 + 对象：「洗到数算得出就停」 |
| **数学与技术符号**（≠ / → / ≥ / A→B） | 只写给眼睛看，念不出口，课堂与口头汇报传不了 | 写成汉字句子：「有的格子空着是对的」 |
| **公文壳**（由 X 说了算 / 由 X 承担 / 就 X 而言） | 绕，读者要拆两层才懂 | 直说动作：「问人」「人来定」 |
| **抽象判断句**（"空着不等于错""这不是 A，是 B"） | 读者得先懂 A，才知道这句在说什么 | 直接给看得见的场景：「有的格子空着是对的，箱子还没还，那格就该空」。（同为"不是 A，是 B"形态的，另计入下方用量条款的配额） |
| **商业与器物化隐喻**（站在 X 的椅子上 · 手上的牌 · 不能动的柱子 · 摊开账本 · 这条腿 · 病根 · 扎手 · 三件套…） | 报告体裁里显得随意，且隐喻一经铺开就变成第二套术语，读者要同时记两套 | 见下方「隐喻清单」逐条替换；判断法：**这个比喻能写进正式报告的目录标题吗？不能就换掉** |

### 隐喻清单 · 场景化与器物化口语（2026-10-20 新增，用户点名）

用户原话：

> 「这是一份严谨的报告，你的措辞却这么口语且一堆 AI 自造词。」
> 「特别是'站在 xxx 椅子上想问题''手上有什么牌''不能动的柱子'（这些我不喜欢的表达）」

问题是**把抽象处境写成实物或动作**（椅子、牌、柱子、账本、腿），单个看有画面，成篇出现就变成一套非正式术语，且与报告体例冲突。

| 不接受的表达 | 换成 |
|---|---|
| 站在 X 的椅子上想问题 / 穿 X 的鞋 | 从 X 视角出发 / 以 X 身份 |
| 手上有什么牌 / 手里的牌 | 可用的政策工具 / 可用资源 |
| 三根不能动的柱子 / 不能动的柱子 | 约束条件 / 不可调整的边界条件 |
| 把账本摊开 / 先摊开账本 | 现状与约束 / 现行口径 |
| 这条腿没长出来 / 两条腿分开跑 | 结构性短板 / 双轨并行 |
| 病根 / 死因 | 失效原因 / 结构性成因 |
| 扎手的数据 / 最刺人的一句 / 更锋利的问题 | 关键数据 / 最值得注意的一句 / 更具挑战的问题（感受词直接删） |
| 逼出的问题 / 咀嚼 | 由此产生的问题 / 权衡 |
| 把人"叫来" / 叫不来人 | 引流 / 吸引到访 |
| 钱进来 / 已经在路上 / 谁来买单 / 嫁接进去 | 资金投入 / 已进入执行期 / 出资主体 / 接入 |
| 被砍掉 | 在预算评审中被削减 |
| 三件套 / 同款模板 | 三类 / 同一模板 |
| 不好卖、不性感、不好拍、抢不走 | 商业转化难度大 / 传播性弱 / 拍摄难度高 / 不可复制 |
| 双刃剑 | 两面性 |
| 往下挖 | 进一步研究 |
| 这是道思考题 / 摊开来看 | 需先行界定 / 现状如下 |

**边界**：引用原文（媒体评论文、受访者原话、行业论断）中的比喻**一律不改**，那是证据，不是本文措辞。只改作者自己的话。

### 报告体裁的第一人称（2026-10-20 新增）

调研、分析、推演、诊断类文档，**不采用角色扮演口吻**。即使内容上是在"假设我是 X 身份"，正文也按客观陈述写：

| 不写 | 改写 |
|---|---|
| 我的 KPI 是三条 / 我自己的处境 | KPI 包含三项 / 约束在于 |
| 我的自问：…… | 需要回答的问题：…… |
| 我看过的案例 / 我认为最值钱的 | 已有案例显示 / 立项理由最充分的一项 |
| 我要的不是更多人 | 目标不是增加客量 |
| 我不下结论 | 本报告不下结论 |

视角设定写在**文首一行说明**里（"视角设定：假设以 X 身份出发"），不要通篇用第一人称维持这个设定。第一人称一多，报告就变成随笔。

> ⚠ **自造词 vs 行业术语，别一刀切**：为某一次教学 / 汇报**临时造**的词（止损、界线、判据、够用）一律换；
> **行业本来就有的术语**（口径、卡点、打通、留痕、血缘）照旧保留 —— 读者在业务里天天见，那是"行话"不是"自造"。
> 判断标准只有一条：**这个词，目标读者在他的日常工作里见过吗？**

### 用量条款 · 先否定再肯定（非必要不用）　｜2026-10-16 新增

**这条不是"禁用"，是"限量"。** 句式本身没错，错在**到处都用**——用一次是力度，用三次就是套路，
读者读到第二处就知道第三处要来，力度归零。所以规矩只有一句：

> **默认直接说后半句；确有必要时才用，全篇只留 1 处（长稿不超过 2 处）。不要到处都用。**

**适用范围（全家族，逐个都算进配额）**

| 家族 | 词面 |
|---|---|
| 对立式 | 不是……而是…… · 并非……而是…… · 不在于……而在于…… · 不是 A，是 B |
| 递进换皮 | 不只是……更要…… · 不仅……更…… · 远不止是…… |
| 对照式 | 表面……实际…… · 看似……实则…… · 与其说……不如说…… |
| 预设立场 | 你以为……其实…… · 说到底…… · 答案恰恰相反 · A 不重要，重要的是 B |

**什么叫"必要"——三条全中才算**

1. **被推翻的那个理解是真实存在的**：读者真的会这么想，或客户现行做法确实如此。不是凭空立一个稻草人。
2. **两个对立面都落在上下文里**：删掉前半句会丢掉一条真信息，读者就看不出这两条路的差别。
3. **用在该用的位置**：方案核心主张首次亮相处，逐字对照两种做法的地方。且全篇没有第二处。

**什么算"没必要"——命中即改**

- 前半句只是让语气"显得谦虚"的铺垫，删掉信息不减 → 删；
- 同一页或相邻页已经用过一次 → 后一处删；
- 拿它当段落组织套路（每页开头都"不是 X，而是 Y"）→ 全部拉平，最多留最关键的 1 处；
- 拿它当标题、口号、金句用 → 删。

**即使必要，也不许换皮**

「不只是……更要……」「不仅……更……」与「不是……而是……」是**同一个动作**，换个递进词不解决问题。
改法只有一个方向——**直接给判断**：

```
❌ 不是把数据搬过来，而是整理成 Agent 易读的形态
❌ 不只是把数据搬过来，更要整理成 Agent 易读的形态     ← 换皮，同罪
✅ 我方建设的价值：把数据整理成 Agent 易读、易算、易追溯的形态
```

**验收**：`check_wording.py` 会统计翻案腔全家族命中数并给出预算结论（`翻案腔用量（非必要不用）`）。
交付前必须让该数字落在预算内；落在预算内的那 1 处，要在交付说明里写明**为什么它算必要**。

## B 级 · 慎用（读语境再定）

| 词 / 句式 | 问题 | 建议 |
|---|---|---|
| 接着用 | 偏口语 | 继续沿用 |
| 心智（"打开 AI 心智"） | 生造提法，读者要猜 | 建立 AI 工作认知 / 学会用 AI 完成工作 |
| 维护人 | 角色界定含糊 | 按岗位性质写：运维人员 / 运营人员 / 业务人员 |
| 在旁边带 | 口语 | 专业人员指导 / 驻场支持 |
| 写死 / 跑通 / 跑起来 | 工程口语 | 固定 / 已验证 / 投入运行 |
| 拉通 / 抓手 / 赋能 / 闭环 / 生态 | 行业黑话，滥用显得空 | 非必要不用；"赋能"改"覆盖"或写具体动作 |
| 其实 / 非常 / 比较 / 一定程度上 / 相对来说 | 空转修饰 | 删 |
| 破折号堆叠、感叹号、表情符号 | 语气过载 | 改用冒号或分号；正式文本不用 emoji |
| 碎片式断句（"数据分散。响应慢。洞察浅。"） | AI 口语味的典型特征 | 合并为完整句：主语 + 判断 |
| 标题与正文重复同一句 | 空转 | 标题给结论，正文给依据 |
| 「不只是……更要……」「不仅……更……」 | 与「不是……而是……」同族：先立误解再推翻 | 直接下判断，不要换成另一个递进词 |

## C 级 · 钦定保留（不要动）

| 术语 | 说明 |
|---|---|
| 召唤 | WorkBuddy 产品既定动作（"召唤专家"），全稿统一用「召唤」 |
| 卡点 | 用户认可的业务用词，保留 |
| 打通 | 重点在"通"（流程、链路贯通）。**不要换成「覆盖」**——覆盖讲的是范围 |
| 口径卡 / 留痕 / 血缘 / 宽表 / 语义层 / 贴源 | 数据治理领域术语，用原词 |
| 5+ 年 / 10+ 家 | 原稿的年限写法，不转成「5 年以上」 |

## D 级 · 通用 AI 句式（第三层判据）

通用 AI 痕迹与个人偏好无关，单列一份完整清单 → **`ai-tells.md`**。

那里有 11 类句式家族的可扫触发词、逐条的方案体裁处置与实测倍率，以及
**17 项"看着像 AI 味但实测站不住"的不收录清单**（被动句、正文问句、句内排比、比喻等）。

**为什么单独一份**：本表 A/B/C 三级是**第二层：个人文风**——"我不喜欢这么写"；
`ai-tells.md` 是**第三层：通用规则**——"AI 公认这么写，与偏好无关"。冲突时按 `edit-discipline.md` 零节裁决。

> ⚠ **第二层允许严于第三层。** 同一个词在通用层面测不出差异、在别处不算问题，
> 只要本方不喜欢，仍可收进 A/B 级。例：名词化、程度直译、复数硬译在通用实测里低于收录门槛，
> 但本表因"精炼""动词选准"两条风格要求仍然要改。**判据不同，不矛盾**，合并成一套才会出错。

## 扫词建议

用 `scripts/check_wording.py` 自动扫 A/B 级词与可疑句式。注意两类误报：

- **C 级词**出现在 A/B 级词的子串里（如"卡点"含"点"）——按词表精确匹配，不做包含判断。
- **工程用语**（CSS 注释、脚本变量里的"兜底""坑位"）不属于页面文案，扫描时应先剥离 `<style>` 与 `<script>`。

脚本另出一行**翻案腔用量预算**结论，专门验收上面的用量条款。默认预算：全篇 **1 处**（≥ 8000 字的长稿 2 处）。
超支时报「重复使用，建议只留最关键的 1 处」；预算内的命中标为「可保留（需在交付说明里写明为什么算必要）」。
