# 编辑纪律：改动的最小化与可验收

> 本文件回答一个问题：**怎么改才不失手。**
> 判据本身（该改什么）见 `banned-words.md` 与 `style-rules.md`；本文件管的是**改动的边界与验收**。
>
> 机制部分吸收自开源项目 **lieflat-less-ai-tone**（MIT，`github.com/larashero3-dotcom/lieflat-less-ai-tone`）——
> 它的规则是按公众号与通用非虚构语料实测标的，**判据不能照搬**（适用边界见第七节），
> 但它那套"把改写约束住"的工程纪律是可迁移的，本文件按方案体裁重新编排。

---

## 零、三层优先级（遇到分歧时的裁决顺序）

同一句话可能同时被两套判据命中，判据指向不一致时，按这个顺序裁决——**序号小的赢**：

| 优先级 | 判据 | 回答 | 来源 |
|---|---|---|---|
| **1** | **功能与语境** | 这段文字在这个位置干什么 | 第一节 |
| **2** | **个人文风** | 按我的偏好该怎么写（A/B/C 词表、白名单） | `banned-words.md` |
| **3** | **通用规则** | 还有哪些通用 AI 痕迹要清 | `ai-tells.md`（明细）、第七节（边界） |

**为什么必须定优先级**：不同判据的来源体裁不同。通用规则按"公众号长文"的分布标定，
用到方案上会出现大面积误判（实测：某通用规则在 64 页方案上命中 **129 处**，
抽样看全是目录索引与交付物清单——那是方案的核心表达方式，不是 AI 痕迹）。
不给优先级，模型就要在两套判据之间临场仲裁，同一份稿子两次改可能得出不同结果。

---

## 一、功能优先：先问"这段文字在这儿干什么"

**动手前先给每个待改元素定位功能，功能位不同，改动的边界就不同。**

### 方案里的功能位清单

| 功能位 | 它要干什么 | 改动边界 |
|---|---|---|
| **标题** | 一句话定调，读者扫读的锚点 | 换措辞可以；**不能改成解释句**，不能加"现状：""小结：""关键点："这类归纳标签，不能塞进来源与背景 |
| **副标题 / 导读** | 补充范围、来源、口径 | 可以说来源与范围；不能抢标题的判断 |
| **小标题 / 标签** | 分类与定位 | 只做归类，不承担论证 |
| **正文判断句** | 给出结论 | 这句是方案的主张。改措辞不改主张；语义强度只允许持平 |
| **证据 / 数据** | 支撑上一句 | 数字与单位只能更准，不能改；不能从"可能"改成"会" |
| **图注** | 说明来源与性质 | 不承担论证，不补充结论 |
| **页脚 / 导航** | 定位 | 不承载内容，只做术语统一 |
| **承诺 / 边界** | 限定条件 | 削弱限定词是篡改，不是优化 |

### 唯一判据

> **改完以后，这个位置还能不能干它原来的活？**

### 实例（样本项目《凯西经营大脑》）

P04 被否掉的一次改动：

```
原文  →  数据分散，临时分析需等待一到两个月
曾改为 →  开标会上的现状：数据分散导致分析滞后
```

**形态没变**（还是一行标题），但**功能变了**：

- 原文是**陈述现象**——把事实摆出来，由读者自己得出结论；
- 改后是**归纳定性**——替读者下了判断，还塞进一个来源标签。

这就是"标题改完还是不是标题"的意思：**不是看它长得像不像标题，是看它还干不干标题的活。**

### 顺带的推论

功能位一旦确定，**改动幅度也就定了**：

- 标题、标签、页脚这类**职能单一的短元素**：只做词语替换，不做句式重组；
- 正文判断句：可以重组句式，但主张不改；
- 图注：只对齐格式，不加工。

## 二、白名单式改写：没命中的，逐字保留

只处理判据里明确列出的问题。**没有命中任何规则的句子必须逐字保留。**

这条是"不为改而改"的**第一道锁**。想改一句话但说不出它违反哪条规则时，答案是**不改**，不是"改得更好一点"。

---

## 三、最小改动：不顺便润色

一句话即使命中规则，**也只能改动解决该问题所必需的部分**：

- 不得顺便润色相邻文字；
- 不得替换没有问题的词语；
- 不得调整语气、详略或信息密度。

**对某处是否命中有把握不足时，保持原文。**

---

## 四、改动可溯源：把"不为改而改"变成可执行的验收

> **每一处改动都必须能指出它对应哪一条规则。指不出来的，撤销，恢复原文。**

这条把一个**态度**变成了一个**动作**。落地方式是定改动集时多一列：

| 页 | 位置 | 原文 | 改后 | **病因（对应哪条规则）** | 说明 |
|---|---|---|---|---|---|

**病因列填不出来的条目，直接从改动集里删掉。**

实测这条很有效：审视上一轮改动时，凡是"改后更漂亮但说不上违反了哪条"的，
基本都能确认是多此一举——例如把「卡点变成起量」改成「关键问题变成起量」，
原文并没有违反任何规则，改动是多余的，属于应该撤销的类型。

---

## 五、信息守恒：不许新增，不许删减

改动后的**每个实词都要能在原文里指出出处**。指不出来就是新增，必须撤销。

### 绝不能凭改写添加

- 姓名、机构名、职务、地名
- 数字、比例、金额、时长、次数
- 日期、时间、先后顺序
- 引语、对话、别人的说法
- 引用来源、出处
- 因果、动机、心理活动
- 原文没写的细节、场景、案例

### 反方向同样禁止

不能删掉原文的观点、结论、**限定词**与**让步**。
把"可能提升"改成"提升"是**篡改语气强度**，不是优化。

写成方案体时尤其要守住这条——方案里的"可能""通常""视情况"往往是有意留出的责任边界，
删掉它等于替客户方做了承诺。

## 六、负面清单：看着像 AI 味，但不许动

以下特征在通用"去 AI 味"攻略里常被点名，**实测站不住，不能据此改文字**。
这张表和判据一样是硬约束。

| 特征 | 为什么不改 |
|---|---|
| 句长、段落长度不够参差 | 实测与人类写作无差别。**不要为了"制造节奏"拆句或拆段** |
| 单字虚词偏少（就 / 很 / 了） | 方向是补不是删；补虚词无法验收，**容易把正式文本改成口语** |
| 反复写全称、少用代词 | 人类比 AI 更常重复同一名词；方案里更需要指代明确 |
| 被动句 | 抽象被动远低于收录门槛 |
| 名词化、长句本身 | 现代汉语书面语的正常写法，人类同样这么用 |
| 正文里的"首先……其次" | 实测与人类无差异；只管小标题编号，正文不管 |
| 句内同构排比（"更高效、更专注、更有创造力"） | 人类用得不比 AI 少 |
| 问句、设问、问句小标题 | 人类远多于 AI，**删掉更不像人写** |
| 比喻本身、比喻独立成段 | 人类是 AI 的 2.4 倍，保留 |
| **四组副题的「从 X，到 Y」句式** | **本方招牌写法**，是方案结构的一部分，不是排比病 |

**最后一条要特别记住**：结构的对仗（四组同名长、副题同句式）是这个文风的核心资产，
通用规则里"打散相邻句同款"那条**不适用于它**。

## 七、通用规则的适用边界（对照表）

把通用去 AI 味规则用到方案体裁上，必须逐条过一遍适用性。
**每条规则的触发词面、改法示例与实测倍率见 `ai-tells.md`；本表只管"用不用"。**

| 通用规则 | 方案体裁下 | 处置 |
|---|---|---|
| 翻案腔（"不是……而是……"及其各色换皮） | **适用，但限量** | 收。这是本技能 A 级已收项，通用规则的贡献是识别"换皮"——见下。**用量纪律：非必要不用，全篇只留 1 处（长稿 ≤2）**，见 `banned-words.md` 用量条款 |
| 提示语引出的冒号（"核心是：""结论："） | **适用** | 收。方案里同样显得空转 |
| 禁用起手式（"说白了""说穿了""先说结论"） | **适用** | 收 |
| 段首零主语评论 | **适用** | 收。方案里常见"值得注意的是"式起段 |
| 翻译腔五型（过长前置定语等） | **适用** | 收，且正好与本技能"主语不省"的要求同向 |
| 把已有的具体数据写回概括表述 | **适用** | 收，与本技能"数字落地"同向 |
| 顿号罗列过密 | **需重划豁免** | **必须保留**目录索引、交付物清单、场景清单、字段清单、章节导航——这些是方案的信息载体，不是凑数 |
| 破折号 | **需重划豁免** | **保留**"标题 —— 并列清单"这种排版用法（用破折号引出下挂的清单，是版式手段） |
| 序数词当小标题 | **需重划豁免** | 保留章节编号（`01/02/03`）与承担指代功能的编号（"见第三节"） |
| 相邻句结构同款 | **不适用** | 方案的结构对仗是刻意的（四组副题同句式），明令保留 |
| 拟人化喻体 | **不适用** | 方案体里基本不用比喻，无处理必要 |

## 八、两套判据的实测冲突面

用两套规则扫同一份 64 页方案（样本项目），结果：

| | 命中量 | 命中内容 |
|---|---|---|
| 个人文风判据（A/B 级词表） | A 级 0 / B 级 13 | 「心智」4 · 「跑通」3 · 「接着用」2 · 「维护人」「在旁边带」「生态」「赋能」各 1 |
| 通用规则（11 条） | 2 条规则命中 | 「顿号罗列过密」129 · 「破折号」4 |

**结论：两者几乎不重叠，是互补关系，不是竞争关系。**

但有两处**真冲突**，需要逐条定夺：

### 冲突一（头对头）：递进句式

- **个人文风判据的 A 级词表**，把「不是……而是……」的改法写成了「**不只是……更要……**」；
- **通用规则第 1 条**把「不仅……更……」「不只是……更要……」也算作**翻案腔家族**——
  先立一个读者并没有的误解，再把它推翻。

**处置**：两者都指向同一个判断——**这类递进句式在方案里是辩解腔**。
推荐改法是**直接给判断**，而不是换个递进词：

```
❌ 不是把数据搬过来，而是整理成 Agent 易读的形态
❌ 不只是把数据搬过来，更要整理成 Agent 易读的形态
✅ 我方建设的价值：把数据整理成 Agent 易读、易算、易追溯的形态
```

**补充（2026-10-16 用户定调）**：这条**不是一刀切的禁用，而是"非必要不用"的限量**——
句式本身可用，但不能到处都用：默认直接说后半句，确有必要时全篇只留 1 处（长稿不超过 2 处）。
"必要"的三条判据与"没必要"的四种情形见 `banned-words.md` 的「用量条款」。

### 冲突二（大面积误伤）：顿号罗列

通用规则在方案上命中 129 处，按它改会拆掉方案的清单结构。
**处置**：该规则的豁免范围必须按方案体裁重划（见第七节）。

## 九、输出前验收清单

逐项打勾，任何一项不过就回到对应条目重改：

- [ ] 每处改动都能指出对应哪一条规则？指不出的已撤销？
- [ ] 改动是否限制在解决问题所必需的最小范围？有没有顺便润色相邻文字？
- [ ] 未命中规则的句子是否**逐字保留**？
- [ ] 改后每个实词能否在原文指出出处？姓名、数字、日期、引语、因果有没有凭空出现？
- [ ] 原文的限定词与让步（"可能""通常""视情况"）有没有被抹掉？判断强度有没有被加重？
- [ ] **改完之后，这个元素还干不干它原来的活？**（标题还是标题、图注还是图注）
- [ ] 有没有为了"制造节奏"调句长或拆段落？
- [ ] 有没有为了"像人写的"补虚词、换代词、加"我/你"？
- [ ] 有没有动结构层（标题层级、页序、页码、交叉引用、配图、版式）？
- [ ] 与标题 / 相邻元素有没有重复？
- [ ] 加长后会不会撑破固定版式？（见 `cheche-html-deck-edit/references/workflow-html-deck.md`）
