# 中文官网站文案句法（2026-11-12 实测提炼）

> 样本：致远互联、东软、金蝶、浪潮、软通动力、汉得、科大讯飞、商汤、智谱、火山引擎、神策、钉钉、用友、华为、中兴、海康、腾讯云、第四范式、MiniMax、旷视。
> 对照：Figma、Stripe、Notion、Linear、Databricks、Snowflake、Scale、Vercel、Supabase、Miro、Intercom、Ramp、Retool、Samsara、Datadog、Gong、Hex、Cohere、Anthropic。
>
> **核心结论：英文站那套（隐喻、Where/For 起句、from X to Y 长定语）翻成中文就是"AI 味"。中文官网自有一套句法，学英文越学越假。**

## 一、首屏（Hero）

### H1 三种可写形态

| 形态 | 例句 | 出处 |
|---|---|---|
| 动宾直说 | 用人工智能建设美好世界 / 引领智能物联新未来 | 讯飞 / 海康 |
| 品类名词短语 | 云计算 大数据服务商 / 企业数智化 用友BIP | 浪潮 / 用友 |
| 场景起句 | AI 时代的新工作方式从这里开始 | 钉钉 |

**禁用**：隐喻（"让 AI 长在业务里"）、`Where/For` 起句（"在这里，团队与智能体一起思考"）、三个并列形容词、"不是…而是…"。

### 副标题：范围列举 + 谁得到什么

火山引擎：`模型、工具、应用到云底座，企业 AI 一站构建`
结构 = 顿号列举范围 → 逗号 → 一句结果。中间不加从属从句。

### 数据条：按证据类别分组，不按业务线分组

钉钉：`2700万+企业组织的选择 · 7亿用户使用钉钉 · 等保三级数据全链路加密`
三类 = **客户规模 / 用户规模 / 合规资质**。

中文政企站数据条推荐四格：**年限 · 交付数量 · 真实影响人数 · 资本或资质背景**。
四个数字必须同一条轴或分属不同类别；两个同类指标并排（如"10万+ 素材"与"10万+ 文书"）会被读成标错。

资质格通常放：等保三级 / ISO 27001 / CMMI / 信创适配。没有就不放，不编。

## 二、公司简介

### 三段式

1. **身份**：全称 + 成立年份 + 股东背景。
2. **履历**：用年份节点，不用"XX 年产业实践"。年份是履历，跨度会被读成"做了 XX 年 AI"。
3. **业务**：几条线 + 客户是谁 + 覆盖哪些行业。

### 讲历史的标准写法：年限 + 沉淀 + 名词

神策：`神策将十一年沉淀的核心数据基础设施，全面封装为 Agent 可自主调用的核心技能套件`

把历史压成一个**可命名的资产**（"十一年沉淀的数据基础设施"），不讲当年的故事。
禁止：`那套批量内容生产，现在是产线的一部分`（口语指代 + 凑对）、`从…走到…再走到…`（三段递进公式）。

### 业务列举

- 数量词用「五条业务线」，不用「提供五大能力」（后者的公文味重）。
- 业务名砍掉冗余后缀：「数据治理与洞察」→「数据治理」，「AI Agent 开发与落地」→「AI Agent」。
- 客户类型可写在产品名后加括号：金蝶「金蝶 AI 星瀚（央国企等大型企业）」。

## 三、团队段

中文政企站团队段只有三种写法：

| 写法 | 例句 |
|---|---|
| 规模 | 「研发与交付人员占比 70% 以上」 |
| 出身 | 「核心成员来自 Adobe、HP、EA 的研发管理岗位」 |
| 年限 | 「平均从业十多年」 |

### 不写的东西

- **三个「懂」**（懂数据、懂业务、懂内容）—— 无法核对，且是排比。
- **「不转包」「不断层」**—— 行业默认，不是亮点；写出来反而暗示行业普遍转包。
- **「从第一次诊断到最终验收」**—— `from X to Y` 直译，中文像说明书。
- **「在客户的业务现场做事」**—— 口语寄存器，像销售饭桌保证。书面写法是「经现场验证」「在客户现场」。

### 推荐结构

> 身份（哪些公司的什么岗位）+ 年限 + 占比。团队分为内容和工程两条线：内容线负责 X，工程线负责 Y。两条线均由自有团队完成。

## 四、句式级红线（写官网前逐条过）

| 禁止 | 为什么 | 改成 |
|---|---|---|
| 那套 / 那时 / 现在还是 | 口语指代，句子成分省略 | 重说具体名词，或直陈 |
| 从…到…（长定语） | 英文 `from X to Y` 直译 | 拆成两句，或直接给时间节点 |
| 不是…而是… | 立一个读者没有的误解再推翻 | 直接说后半句 |
| 对偶金句（字数对齐、概念抽象） | 换个主语还成立 = 不承载信息 | 陈述句：给时间、主体、动作 |
| 三个并列形容词 / 三个「懂」 | 排比，零信息 | 换成可核对的身份、数量、职责 |
| 文言化（予…以…之力 / 授…以渔） | 读者要还原语法，多花一步 | 白话动宾 |
| 赋能 / 拉通 / 抓手 / 闭环 / 生态 | 黑话，一线公司官网出现率为零 | 具体动作名词 |
| 十二年产业实践 | 跨度被读成"十二年 AI" | 三个年份节点 |
| 中英混排（STATE-BACKED / AI LANDING） | 英文用法常错，且不像中文官网 | 全中文 |
| 拟人 / 生命力隐喻（长在 / 扎根 / 生长） | 英文站语感，中文政企站不用 | 动宾直说 |
| 否定式卖点（拒做 X / 不做演示品 / 不做外包） | 把行业底线当差异，反而暗示同行普遍如此 | 直接写自己交付出来的是什么 |

### 板块导语：只写说明书，不写故事（2026-11-14 补充）

板块导语（每条业务线标题下的那句概述）必须是**说明书文体**：短句、动宾结构、陈述事实，读者扫一眼就知道这条线做什么、给谁做。

| 禁止 | 为什么 | 改成 |
|---|---|---|
| 叙事开场（先讲一个场景或一个客户的困境，再引出业务） | 官网不是案例文章，读者是来找“你能做什么”，不是听故事 | 第一句就说这条线做什么 |
| 设悬念、留钩子（“真正的问题不在数据本身”） | 广告文案套路，政企读者当成营销话术跳过 | 直接给结论 |
| 导语复述子段落的正文事实 | 导语与正文重复，页面像同一句话说两遍 | 导语只给范围与对象，细节留给子段落 |
| 比喻式板块标题（“一栋楼，装下企业要的 AI”） | 比喻要多做一层转换，换个客户就不成立 | 用业务名词直说 |

自检：把导语单独抽出来读，像故事开头而不像产品说明，重写。

### 数据条只放可计数项（2026-11-14 补充）

数据条每一格必须是**能核对到具体数字的项**：年份、客户数、项目数、人数、资质编号。

| 禁止 | 为什么 |
|---|---|
| 把能力描述塞进数字位（“四级 严格权限管控矩阵”） | 读者会去找“四级”是什么标准，找不到就失去信任 |
| 造词式指标（同页一处“20+ 自建 Agent”、另一处“20+ 客户团队自建 Agent”） | 同页两处口径不同，读起来像没对齐 |
| 虚数包装（“100+ 精选交付项目”与已定的 21 个冲突） | 数字被追问就崩 |

规则：同一页所有数字必须能追溯到同一口径来源；不能追溯的删掉，不换成形容词。

### 资质横栏：按体系类型分组，不逐条堆（2026-11-16 补充）

官网底部或「关于我们」页的资质区，常出现七八张证书并排。逐条列出来会变成一串读者不认识的缩写，扫过去没有信息。正确写法是先分类型，每类给一句总结，具体名称放在类目里。

四类固定分法：

| 类型 | 放什么 | 写法 |
|---|---|---|
| 管理体系认证 | ISO 9001 质量、ISO/IEC 27001 信息安全、ISO/IEC 20000-1 IT 服务、ISO 14001 环境、ISO 45001 职业健康安全 | 「五项管理体系认证，覆盖质量、信息安全、IT 服务、环境与职业健康安全」 |
| 经营许可 | 增值电信业务经营许可证等带编号的行政许可 | 「增值电信业务经营许可证（合字 B2-20220450）」——许可证类必须带编号，不带编号等于没写 |
| 创新与专项认定 | 高新技术企业、专精特新、科技小巨人、市区级专项资金 | 「高新技术企业（2025 年）、上海市专精特新中小企业（2026–2029）、杨浦区科技小巨人（2024 年度）」——每项带年份或有效期 |
| 官方授权与合作 | 平台方授权、政府场景入选 | 「腾讯 WorkBuddy / CodeBuddy 官方授权合作伙伴」；场景入选写清批次与联合方 |

禁止：

- **七张证书平铺一栏**（ISO 27001 / ISO 20000-1 / ISO 9001 / ISO 14001 / ISO 45001 / 高新技术企业 / 专精特新）——读者数不出重点，也不知道哪张跟自己的采购决策有关。
- **只写缩写不带解释**（ISO/IEC 27001 单独成格）——政企采购看的是「信息安全」这个结论。
- **用「多项权威认证」「资质齐全」代替具体名称**——形容词化，读者核不了。
- **过期不标注**（专精特新、科技小巨人都有有效期，写到期年份，不写「多年蝉联」）。

自检：把资质区遮住名称只看类目，能不能判断这家公司能不能接你的项目（信息安全过不过、有没有电信业务资格、是不是政府认定过的创新主体）。判断不了就重排。

## 五、交付前自检

1. 把 H1 单独念一遍：有没有一个具体动作或一个具体品类？
2. 副标题能不能一口气读完？超过 25 字就砍。
3. 数据条四格，读数时会不会有两格像在比同类指标？
4. 全文搜「那/这/它」指代词：官网正文里的指代词应接近零。
5. 全文搜「不是」「而是」：应为 0。
6. 团队段有没有形容词？有就换成数字或岗位。
7. 每一句问：换个公司名还成立吗？成立就删。
8. 每条业务线的板块导语抽出来单独读：像说明书还是像故事？像故事就重写。
9. 全文搜「拒」「不做」「不搞」：否定式卖点应为 0。
10. 数据条逐格问：这个数字从哪来？答不上来就删格，不换成形容词。
11. 资质区遮住名称只看类目：能不能判断这家公司接得了你的项目？判断不了就按体系类型重排。
